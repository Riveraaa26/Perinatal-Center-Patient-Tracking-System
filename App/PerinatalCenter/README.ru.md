# Запуск на Windows в Qt Creator

## 1. Подготовьте учебную базу

Понадобятся PostgreSQL с pgAdmin и расширением pgcrypto, Qt Creator, комплект Desktop Qt 6.12.0 MinGW 64-bit с Qt Quick, Quick Controls и Qt SQL, CMake и Ninja. Команды и названия DLL ниже относятся к 64-разрядному комплекту. В ходе подготовки проверен Linux с Qt 6.8.2 и PostgreSQL 17.12.

1. В pgAdmin на своём локальном сервере создайте пустую базу **Perinatal** с кодировкой UTF8. Откройте Query Tool именно для неё. Для скриптов используйте владельца базы с правами создавать расширения и SQL-роли.
2. Открывайте и выполняйте по одному файлу из папки **sql**. Сначала **01_create_fresh.sql** (новые таблицы), затем **03_demo_departments.sql** (четыре отделения и восемь палат).
3. Откройте **05_create_first_admin_pgadmin.sql** в Query Tool. В двух строках объявления переменных замените значения справа от `:=` на придуманные логин и пароль первого администратора приложения. Например, логин может иметь вид `admin@example.test`. Пароль — от 12 символов, максимум 72 байта UTF-8. Выполните запрос, запомните данные. Заполненную копию со своим паролем не включайте в проект.
4. Аналогично выполните **06_create_db_login_template.sql**. В объявлении переменной задайте отдельный пароль для SQL-роли `perinatal_app`. Он понадобится в параметрах запуска. Если такая роль уже была в этом локальном кластере, используется её прежний пароль. Используйте выделенный тестовый экземпляр PostgreSQL.
5. По желанию выполните **07_demo_patients.sql**. Он добавит две вымышленные карты без размещения. Для скринкаста можно начать с пустого реестра.

## 2. Откройте и запустите проект

1. Распакуйте архив целиком в короткий путь, например `C:\Projects\Perinatal`. В Qt Creator выберите **Файл → Открыть файл или проект**. Укажите **App/PerinatalCenter/CMakeLists.txt**.
2. Выберите **Desktop Qt 6.12.0 MinGW 64-bit** и пустой каталог сборки. Оставьте `PERINATAL_TEST_DRIVER=OFF`. Нажмите **Configure Project**.
3. В разделе **Проекты → Запуск → Окружение** добавьте значения из таблицы. Учётная запись PostgreSQL подключает приложение к БД. Учётная запись сотрудника из шага 3 вводится в окно «Вход в систему».

| Переменная | Значение для локального стенда |
|---|---|
| PERINATAL_DB_HOST | 127.0.0.1 |
| PERINATAL_DB_PORT | Порт вашей установки, обычно 5432 |
| PERINATAL_DB_NAME | Perinatal, с учётом регистра |
| PERINATAL_DB_USER | perinatal_app |
| PERINATAL_DB_PASSWORD | Ваш пароль из скрипта 06 |
| PERINATAL_DB_SSLMODE | prefer для локального теста. Для согласованной удалённой тестовой копии с сертификатом — verify-full |

4. Выполните **Сборка → Запустить CMake**, затем **Ctrl+B** и **Ctrl+R**. Войдите первым администратором. На странице сотрудников создайте медсестру, врача и заведующую. Выберите роль и сохраните сгенерированный пароль перед закрытием сообщения.
5. Выйдите и войдите сотрудником нужной роли. Для перехода из списка отделений к палатам используется двойной щелчок. В реестре один щелчок выбирает пациентку. Перевод и выписка требуют отдельного подтверждения.

## Если запуск остановился

| Симптом | Что проверить |
|---|---|
| CMake не находит Qt6, QuickControls2 или Sql | Выбран комплект Desktop с нужными модулями и его компилятором MinGW. После смены комплекта используйте новый каталог сборки. |
| QPSQL driver not loaded | В каталоге плагинов выбранного Qt проверьте `sqldrivers/qsqlpsql.dll`. В окружении запуска PATH должны быть доступны совместимые 64-разрядные `libpq.dll` и её зависимости. Для диагностики включите `QT_DEBUG_PLUGINS=1` и откройте «Вывод приложения». При отсутствии плагина установите или соберите QPSQL того же комплекта Qt. |
| Нет связи или пароль PostgreSQL отклонён | Проверьте службу PostgreSQL, точное имя базы, порт, права SQL-роли. Проверьте соединение в pgAdmin с теми же параметрами. После исправления перезапустите приложение. |
| Ошибка авторизации или журнала | Убедитесь, что выполнены 01, 05, 06, расширение pgcrypto установлено в доступной схеме. После миграции проверьте роль сотрудника и формат пароля. |
| Сохранение не подтверждено после обрыва связи | Восстановите соединение и проверьте историю карты и реестр, прежде чем повторять действие. Сервер мог принять COMMIT непосредственно перед обрывом связи. |
