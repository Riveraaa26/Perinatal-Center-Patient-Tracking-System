# Подключение к PostgreSQL команды

Дамп общей базы отсутствовал. Схема тестового стенда восстановлена по запросам в yadro.cpp, ERD.png и разделу 4 спецификации. Все запуски выполнены на вымышленных данных в отдельном локальном кластере.

## Что сверяет ответственный за базу

| Объект | Требование клиента |
|---|---|
| Схема и кодировка | Таблицы видны через search_path клиента. Скрипт 06 рассчитан на public. UTF8, согласованные часы и часовой пояс сервера/рабочих мест, обычный режим READ COMMITTED. |
| role, employee, authorizations | id, role_id, employee_id, block boolean, login, password. Одна строка входа на сотрудника, логин уникален. Четыре точных значения role_name перечислены в 01. При других названиях согласуйте соответствие. |
| patient | id, name, sour_name, policy, pregnancy_period, disease, discharge_date, discharge_recommendations. Полис хранится как строка из 16 цифр. Числовой тип теряет ведущие нули. Срок задан в неделях. При отличиях требуется отдельное согласование преобразования. |
| department, chamber | department_id, number, capacity, disease, current_load. Номер палаты целочисленный, уникален внутри отделения. Вид отделения хранит department.kind — ward, operating, postpartum. Операционная занимает одну строку chamber вместимостью 1. |
| transfer | id последовательно назначается БД, patient_id, employee_id, nullable chamber_id, date. Последний id определяет размещение. Нулевой chamber_id в смысле SQL NULL обозначает выписку. Отсутствие событий обозначает зарегистрированную пациентку без койки. |
| Ссылки и аудит | PK, FK, последовательности, ограничения вместимости, права и триггеры. Проверьте отсутствие каскадного удаления истории. Аудит содержит сотрудника, действие, объект, идентификатор и время. |
| Старая история | Сверьте порядок id и фактический порядок событий, особенно после импорта. Проверьте незавершённые и повторные госпитализации, старые обозначения выписки, переполнения, совпадающие полисы и логины. Клиент ведёт один случай на полис. |

## Проверка существующей схемы

1. Ответственный делает резервную копию и восстанавливает её в отдельную тестовую БД. Сначала используйте синтетическую или обезличенную копию. Для одного сравнения структуры достаточно экспорта schema-only.
2. Откройте **00_inspect.sql** на копии. Сопоставьте фактические типы, значения по умолчанию, уникальность, внешние ключи и пользовательские триггеры с **01_create_fresh.sql**. Скрипт 01 применяется к пустой БД. При отличиях установите смысл полей с разработчиком БД.
3. Прочитайте **02_upgrade_existing.sql**. Он изменяет тип поля пароля, добавляет сведения о выписке и тип отделения, разрешает NULL в transfer.chamber_id, создаёт уникальные индексы и аудит, пересчитывает current_load по истории. Для двух точных названий демостенда тип распознаётся автоматически. Проверьте и назначьте operating и postpartum для остальных соответствующих отделений на копии. Переименование после настройки сохраняет тип.
4. Остановите остальные клиенты копии. Для запуска 02 в той же вкладке Query Tool сначала выполните `SET perinatal.migration_target = 'точное_имя_копии';`. Только при подтверждённом хранении старых паролей открытым текстом дополнительно выполните `SET perinatal.legacy_plaintext = 'confirmed';`. Неопознанные форматы с префиксом $, пустые и чрезмерно длинные пароли требуют разбора. Другие старые хеши тоже нельзя объявлять открытым текстом. После преобразования старая версия с простым сравнением паролей больше не сможет выполнить вход.
5. Весь 02 выполняется в одной транзакции. Ошибка ограничений, неподтверждённый формат паролей или пользовательский триггер на transfer/chamber останавливают миграцию. После ошибки в pgAdmin выполните ROLLBACK, выясните причину на копии. Для отката уже подтверждённой миграции восстановите резервную копию.
6. Запустите **04_diagnostics.sql**. Для каждой палаты mismatch должен быть false, calculated_load в пределах от 0 до capacity. Проверьте числа вручную на нескольких историях. Для старых неопределённых дат миграция сохраняет NULL.
7. Назначьте SQL-роли клиента привилегии по образцу 06 на копии. Проверьте наследуемые права и прежние GRANT отдельно. Задайте параметры подключения из README.ru.md, выполните сценарий DEMO.ru.md. В общей БД изменения в рамках этой поставки не выполнялись.

## Граница учебной архитектуры

Спецификация также описывает браузер и HTTPS API. В этой поставке QML вызывает C++, C++ использует QPSQL напрямую. Авторизация сотрудника выполняется внутри приложения. Пользователь с паролем общей SQL-роли может обратиться к БД отдельным клиентом. Такая схема рассчитана на доверенный учебный стенд с вымышленными данными. Межклиентская синхронизация рассчитана на запись через эту версию приложения. Другой клиент, напрямую меняющий историю без тех же блокировок, нарушает это условие.
